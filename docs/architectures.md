# 專案結構

本文件提供目錄與系統層級的導覽。遊戲體驗與目標見 [README](../README.md)，開發共識與維護規則見 [AGENTS](../AGENTS.md)，實作細節見 [系統說明](systems.md)。

## 目錄分工

| 目錄 | 用途 |
| --- | --- |
| `assets/` | 可編輯的遊戲資料、模型、圖片、材質、字型與翻譯；`data/` 分為關卡、兵種、塔與地塊配置 |
| `scenes/` | 遊戲入口及依功能分類的場景；各分類的 `components/` 保存共用範本 |
| `scripts/` | 依功能分類的遊戲規則、流程協調與畫面控制 |
| `native/` | C++ 道路圖、局部搜尋、路線池與編輯檢查核心；`godot-cpp/` 是固定版本 SDK |
| `addons/` | Godot 編輯器工具，目前包含波次編輯器 |
| `tests/` | 依功能分類的 Godot／C++ 測試，以及共用測試資料 |
| `tools/` | 原生建置、離線素材產生、Web 測試匯出與驗證工具 |
| `reports/` | 精簡保留的歷史效能結論，不存例行測試產物 |
| `docs/` | 架構導覽與詳細系統說明 |
| `bin/` | 遊戲執行需要的原生擴充建置產物 |
| `build/`、`.godot/` | 匯出成品與本機快取，不是遊戲設定來源 |

## 遊戲系統

| 功能 | 責任 |
| --- | --- |
| 開始選單 `menus` | 明確保存的 3D 橋景、同場景選圖與本局設定流程、唯讀地形預覽、主畫布設定宿主、確認後切換正式關卡；不載入遊戲模擬系統 |
| 設定 `settings` | 可重用的主畫布 Control 頁面、通用選項列與引擎設定介接；宿主管理開關、背景輸入鎖定及遊戲流程 |
| 共用介面 `interface` | 跨場景白色過渡及期間的輸入攔截，持續存在於主畫面與關卡之間；呼叫者決定切換目標與遊戲狀態 |
| 關卡 `levels` | 載入地形與端點、ACT／波次排程、入口擴張、時間線與暫停 |
| 卡牌 `cards` | 建造卡組合、手牌、旋轉預覽、放置意圖與商店交易；顯示與交易分開管理 |
| 地圖 `map` | 格子資料、道路接口與批次變更；外觀變種和浮起動畫獨立管理 |
| 導航 `navigation` | 道路快照、原生介接、兵種評分、有限候選池、路線配額與除錯顯示 |
| 敵人 `enemies` | 兵種設定、出生、固定行程移動；模型、避讓及頭頂狀態由顯示層處理 |
| 塔與戰鬥 `towers`／`combat` | 塔種、占格、威脅、索敵、攻擊、命中與效果 |
| 鏡頭與環境 `camera`／`environment` | 鏡頭平移、縮放與旋轉、雲海與環境呈現 |

## scripts/ 結構

第一層按遊戲功能分類，各功能根目錄保留執行入口與主要協調器。設定、出生、介面或渲染已形成獨立責任時才建立子目錄；小型功能維持平面結構。場景放在 `scenes/`、可編輯內容放在 `assets/`，腳本目錄描述的是程式責任。

```text
scripts/
├── camera/                  地圖鏡頭
├── cards/                   選牌、旋轉與放置意圖
│   ├── definitions/         建造卡、地塊配置與候選權重
│   ├── presentation/        卡面、手牌、商店畫面與世界預覽
│   └── shop/                金幣、商品、購買與重刷
├── combat/                  戰鬥主迴圈與敵人格子索引
│   ├── attacks/             攻擊策略與發射時的傷害快照
│   ├── effects/             命中後的規則效果
│   └── rendering/           攻擊軌跡與回收式爆散特效
├── enemies/                 單隻敵人的移動、生命與狀態
│   ├── presentation/        頭頂狀態與獨立開波按鈕
│   ├── rendering/           模型、步態、MultiMesh 與視覺避讓
│   ├── spawning/            出生排程、行程快照與敵群生命週期
│   └── troops/              兵種 Resource 與自動發現目錄
├── environment/             雲海等環境呈現
├── interface/               跨場景過渡與共用輸入攔截
├── levels/                  關卡階段與 ACT／波次進度
│   ├── definitions/         Level／ACT／Wave／SpawnGroup 設定
│   ├── expansion/           ACT 之間的新入口候選與提交
│   └── presentation/        HUD、時間線、手動開波與暫停介面
├── menus/                   開始選單、選圖流程與設定宿主
├── settings/                可重用設定頁面、選項呈現與設定介接
├── map/
│   ├── terrain/             地形場景端點、貼齊與配置驗證
│   └── tile/                道路接口、批次地塊與每格資料集合
│       └── appearance/      柱子、木橋、顯示地圖與浮起動畫
├── navigation/              道路快照、原生介接與重建協調
│   ├── routes/              候選行程、兵種評分與配額機率
│   └── visualization/       F1／F2 路線與地塊除錯顯示
└── towers/                  塔種、塔實例、占格與地圖提交
```

### 關卡與出生

| 範圍 | 責任與主要協作 |
| --- | --- |
| `levels/` | 關卡 session 在子節點就緒前安裝地形及端點，推進準備、開場等待、戰鬥、ACT 擴張與結束狀態，協調手牌、商店及開波權限 |
| `levels/definitions/` | `LevelDefinition` → `ActDefinition` → `WaveDefinition` → `WaveSpawnGroup` 保存可編輯配方與設定驗證；Level 的翻譯 key 由 ID 推導，起終點只由地形端點提供，ACT 各自決定完成後是否擴張入口；編輯器外掛、關卡和生成系統共用這些型別 |
| `levels/expansion/` | 依已提交道路搜尋新入口候選，處理方向選擇、預覽和新增道路／端點；完成後由 session 恢復下一波準備 |
| `levels/presentation/` | 將 session 進度投影到時間線、起點對話框、餘額與下一波兵種列；協調準備期流量預覽、處理倍速、暫停過渡、選單與玩家意圖 |
| `enemies/spawning/` | 把波次配方與已準備的導航計畫轉成帶有整數出生刻度、路線及數值快照的排程，批次準備各兵種／入口的配額並共用該波唯讀世界座標，再實際生成敵人，追蹤待出生／存活／擊殺／抵達並判定清場 |

`levels/` 也提供自動資源目錄、DAG 前置檢查、通關 ID 保存及一次性交接。`menus/` 接收目錄的顯示資料並延遲建立單一預覽；`LevelSession` 只在最後一波完成時回報通關，不依賴選單 UI。

關卡決定「目前進行哪一波、何時允許開波」；出生模組決定「該波每位成員何時出生、採用哪份已固定資料」。出生排程與敵群放在一起，因此正式關卡與獨立測試場景可共用同一個生成入口。

`menus/` 的獨立啟動場景先委託 `enemies/rendering/` 的持續顯示服務，依材質與繪製方式挑代表、使用既有 renderer 預熱並保留資源，再進主選單；不初始化遊戲模擬。選圖後的載入由 `interface/` 的持續轉場層透過目標場景指定方法協調；LevelSession 準備路線及尚未涵蓋的顯示組合。啟動與轉場共用載入 Control；轉場層不依賴敵人或導航模組。

### 建造、地圖與導航

| 範圍 | 責任與主要協作 |
| --- | --- |
| `cards/` | 管理手牌庫存、選卡與旋轉狀態，送出預覽／放置意圖，依關卡階段及商店狀態切換輸入；成功提交後才消耗卡牌 |
| `cards/definitions/` | `BuildCard` 組合塔種、價格與 `TilePreset`；候選資源保存各塔的地塊檔案引用與相對權重 |
| `cards/shop/` | 保存金幣及商品庫存，處理波次獎勵、購買、重刷與抽牌 RNG，將結果交給手牌與商店畫面 |
| `cards/presentation/` | 卡面、名稱、地塊示意、扇形布局、手牌／商品動畫，以及世界中的放置模型和旋轉提示 |
| `towers/` | `TowerDefinition` 提供塔種設定，`DefenseTower` 保存實例狀態；`TowerMap` 驗證整組地塊、占格、端點、BFS 連通性及固定行程，提交塔與道路並更新威脅 |
| `map/terrain/` | 讀取地形場景中的 Start／Goal 與巢狀變換，執行端點貼齊、數量、重疊和道路可達性驗證，供關卡載入與編輯器共用 |
| `map/tile/` | 管理格座標與接口契約、道路批次變更及鄰格刷新；`TileParameters` 保存單格資料，store 維護每張地圖的資料集合、塔覆蓋與按兵種快取的成本陣列 |
| `map/tile/appearance/` | 根據已提交道路選擇合法柱子／木橋外觀，以獨立顯示 GridMap 播放差異格的浮起動畫；邏輯道路立即可用 |
| `navigation/` | 從 GridMap 和障礙取得 packed snapshot，協調原生建圖、額外端點、編輯檢查、revision 及快取失效，向生成器與除錯層提供計畫 API |
| `navigation/routes/` | 協調原生批次候選探索／展開／去環／評分與機率表，管理幾何池及兵種快取、完整行程快照與批次配額；從已分配行程累加兵種／入口／有向區段流量；正式摘要與按需除錯聯集分開 |
| `navigation/visualization/` | 讀取當波行程與地塊資料，繪製 F1／F2、圖例及參數，另從完整配額行程保留抵達相位、以查表及批次網格顯示玩家流量筆觸；局部路線輔助資料也留在此呈現邊界 |

地塊資料集合在 `map/tile/` 實作，執行時由 `PortalMap` 為每張地圖持有一份；導航消費其成本陣列，塔系統透過控制器提交覆蓋變更。store 快取評分輸入，實際路線探索由導航及原生核心完成，檔案位置與實例持有者在這裡分開說明。

### 戰鬥、敵人與呈現

| 範圍 | 責任與主要協作 |
| --- | --- |
| `enemies/` | 每隻敵人持有生命／護盾、狀態效果、位置與完整固定行程，沿行程移動並發出抵達、受傷及死亡通知；共用邏輯預設留在本層 |
| `enemies/troops/` | `Troop` 描述數值、路線偏好、模型與圖示，`TroopCatalog` 發現並共用資源，供波次編輯器、生成器和導航使用 |
| `combat/` | 在移動完成後建立一次敵人格子索引，執行索敵、瞄準、冷卻及飛行攻擊結算；塔與 AOE 共用該索引 |
| `combat/attacks/` | 箭矢、光束及拋射物描述投遞策略，`AttackPayload` 保存發射時的傷害／效果快照，讓飛行中的攻擊可獨立於來源塔結算 |
| `combat/effects/` | 描述命中後對敵人施加的規則效果，例如減速的倍率、期限及對應狀態圖示 |
| `combat/rendering/` | 把已存在的飛行／命中資料轉成軌跡、箭矢、AOE 與死亡爆散，管理特效回收及動畫 |
| `enemies/rendering/` | 把邏輯位置轉成模型姿態、GPU 步態、側向避讓與各網格獨立的 MultiMesh instance 資料；離線 GPU 模型 Resource 保存網格與步態參數，共用同一 shader。外部模型在此管理骨架／動畫及顯示轉換 |
| `enemies/presentation/` | 依 renderer 提供的頭頂世界座標投影血條、護盾、技能與效果圖示；管理共用圖集、可重用 instance buffer 與單一 2D MultiMesh 提交。另提供獨立場景的開波按鈕。螢幕投影與 3D 模型渲染各自維護 |
| `camera/`、`environment/` | 分別管理平移／縮放／環形拖曳旋轉／鏡頭邊界，以及雲海材質和範圍；維持獨立的小型功能目錄 |

`presentation/` 集中螢幕介面與玩家操作回饋；`rendering/` 集中模型、幾何、姿態與世界特效。敵人的狀態顯示會讀取模型層提供的避讓後座標，因此兩者透過顯示資料協作。

`assets/materials/` 與 `assets/shaders/` 提供道路、塔及敵人共用的不透明純色材質；各功能只引用 Resource，不在執行期轉換或複製。顏色、表面參數及剛體步態由 `tools/assets/` 離線寫入網格，保留特殊效果自己的材質。格式與重建流程見 [材質說明](../assets/materials/README.md)。

### 主要協作流程

1. **建造**：卡牌意圖 → 塔系統重新驗證 → 提交地塊／塔／覆蓋 → 導航重建或失效 → 地圖及卡牌畫面更新。
2. **開波**：關卡配方與階段 → 導航準備各入口／兵種計畫 → 出生模組分配並固定完整行程／數值 → 按整數刻度生成 → 敵人移動 → 清場後關卡推進。
3. **每幀**：敵人更新邏輯位置 → 戰鬥建立索引並結算 → 模型層提交姿態與避讓後位置 → UI 投影頭頂狀態，特效層繪製已結算事件。

新增內容優先沿用對應功能與上述責任邊界。共用常數跟隨所屬功能，Resource 型別跟隨其資料領域；可編輯的 `.tres` 實例仍放 `assets/data/`。UI、渲染、測試與工具各自透過現有介面協作，搬移腳本時同步更新明確路徑並保留 UID。

## 資料與責任邊界

遊戲設定由 `assets/data/` 的 Resource 提供，場景組合可編輯的節點與外觀，GDScript 協調規則與流程。C++ 處理道路幾何與搜尋，不持有商店、關卡進度或敵人流量。血量、位置、冷卻與固定行程等即時狀態由各遊戲實體保存，不寫回共用設定。

建造流程由卡牌送出意圖，放置系統驗證整組道路與塔占格後提交地圖，再通知導航與顯示更新。預覽只讀候選資料，實際放置會再次驗證。導航從道路快照建立共用入口圖，再依兵種與起點建立候選路線及配額；開波時固定敵人的完整行程，移動期間不重新選路。

地形、戰鬥與行程是邏輯資料；地塊浮起、敵人避讓、特效及 UI 是呈現。動畫不能延後地圖提交，也不能改寫路線或命中結果。編輯器外掛、離線工具與歷史報告不參與正式遊戲執行。

## 開發支援

測試依功能分類；JSON、截圖與 log 放在已忽略的 `.godot/`，`reports/` 只保存需要長期參考的摘要。一次性壓測與重複純預覽場景已清除，保留功能與實際繪製回歸。素材工具產生可編輯的遊戲資產，原生工具將 C++ 核心建置到 `bin/`。正式匯出排除測試、工具、報告、技術文件與原生 SDK。

更細的操作入口見 [場景導覽](../scenes/README.md)、[測試說明](../tests/README.md)、[工具說明](../tools/README.md)與 [原生核心](../native/README.md)。
