# 不透明純色模型共用材質與 Web 對照（2026-10-23）

道路、木橋、塔、端點非發光零件及三種正式敵人已共用一份 `assets/materials/solid_color.tres`。本次 AMD／Edge 三輪實測，啟動至主選單中位數由 **31.68 s 降至 20.11 s**（減少 11.57 s，約 36.5%）。256 混兵的穩態平均幀時間下降，但 **P99 幾乎不變，首次出兵仍有約 0.29 s 尖峰**。選圖至關卡載入沒有縮短。

## 實作及外觀

- 材質是同一個 Resource，不只共用 shader source。顏色寫入 COLOR；粗糙度／反光寫入 CUSTOM1，保留亮木板與石材的差異。三兵種擺幅、起伏、側擺及取樣間隔寫入 CUSTOM0，UV／UV2 保留支點，靜態模型略過步態。
- Soldier 仍依距離推進，Quickfeet／Heavy 仍精確重現原本 17 個線性關鍵影格、各自週期與停止姿勢，Quickfeet 保留 3 倍播放。三種模型維持各自 MultiMesh，原有每幀 transform／phase／blend 提交不增加欄位或 CPU 步驟。
- 普通石路、木橋各為 1 個 surface；帶柱道路為純色道路＋柱底效果，共 2 個。保留來源場景節點、變換、動畫、MeshLibrary 項目與道路資料；沒有重生原型或重設地圖。
- 雲海、柱底漸變／生長、端點發光、透明攻擊／死亡特效、2D UI 及任意外部匯入模型仍有自己的材質。啟動仍實際繪製普通 MeshInstance 與敵人 MultiMesh，涵蓋不同繪製路徑。
- 離線工具檢查材質設定，排除特殊材質；已烘焙資料不重複打包，避免累積法線量化誤差。格式與重建方法見 [材質說明](../assets/materials/README.md)。

實際 Windows Compatibility／RTX 3050 畫面驗證：五個純色／表面參數樣本幾乎逐像素一致；14 個道路庫項目與兩個塔網格的前景平均 RGB 誤差最高 0.001742（0–1 範圍，約 0.44／255；頂點色與法線儲存量化），塔兩部分為零。Quickfeet／Heavy 六個姿勢的誤差最高約 0.000634。逐頂點步態最大位置誤差 1.20e-7 世界單位，法線誤差約 1.07e-4。

## 本次測試條件

- `feat/outer_game_ui`，Godot 4.7.2 Compatibility，Web release、單執行緒 GDExtension。兩版都已使用三兵種 GPU MultiMesh，這次只比較共用材質／網格表面整合。
- Edge 155.0.4283.62、每次新開有視窗 session、瀏覽器 viewport 1280×800。實際 GPU：`ANGLE (AMD, AMD Radeon(TM) Graphics (0x00001636) Direct3D11 vs_5_0 ps_5_0, D3D11)`。rAF 基準約 6.94 ms（144 Hz）；下表使用真實 rAF 間隔，不用 Godot 可能限制／平滑過的 delta 代替。
- 正式啟動 → 主選單 → 選圖 → 本局設定 → 正式 level，實際點擊按鈕。測試只在該次程序內替換 Level 配方，沒有修改正式關卡或兵種數值。
- 32×32 範圍，16 個 7×7 房間與水平／垂直連接，共 809 道路格；入口 (0,3)、終點 (31,27)，16 座 Sentry。與上一份 GPU 混兵報告使用同一合成配方，不是歷史 801 格地圖。
- 同刻出生 Soldier 86／Quickfeet 85／Heavy 85；副本血量 1,000,000、移速倍率 0.45、波次速度 2.5，Quickfeet 測試 base cost 0.25。原雲、HUD、狀態、卡牌、塔與戰鬥啟用；固定相機 size 42、near 0.1／far 150，實際地形與模型均在畫面內。
- 舊／新交錯各三次 session，每次兩波。開波保留原本 1.5 s 等待，出齊後觀察 14 s；穩態取最後 500 個 rAF 間隔，尖峰取該波整個觀察窗口。兩波之間只移除測試敵群，保留場景與快取。12 個窗口結束時存活數均為 256。
- 攔截原有 WebGL 呼叫，未增加編譯同步查詢；LINK_STATUS 時間包含等待編譯／連結完成，不能進一步拆成 ANGLE 與驅動時間。全部正式量測 browser error／page error 為零。

## 編譯與載入

各時間為三次 session 的中位數。啟動包含本機下載、WASM／引擎初始化、預熱及首次主選單繪製；關卡載入以原生轉場 started → finished 計時，不混入人工點擊與選圖停留。

| 項目 | 修改前 | 修改後 |
| --- | ---: | ---: |
| 導航至主選單可操作 | 31.68 s | 20.11 s |
| 選圖確認至關卡轉場完成 | 2.01 s | 2.24 s |
| 啟動 LINK_STATUS 等待加總 | 27.80 s | 16.42 s |
| 啟動 linkProgram 提交 | 65 | 55 |
| 啟動 compileShader 提交 | 130 | 110 |
| 整個兩波 session 的 linkProgram 提交中位數 | 84 | 72 |
| 整個兩波 session 的 compileShader 提交中位數 | 168 | 144 |

啟動等待減少 11.38 s，與整體啟動減少 11.57 s 接近，支持本次縮短主要來自減少不同材質程式的編譯等待。共用材質在這個負載產生 **8 個引擎 program**，全部在啟動完成，三輪等待加總為 4.30–5.30 s；進關卡與兩波沒有新增這一組 program。不同繪製模式與引擎變體仍存在，因此不是「只剩一次 shader 編譯」。

兩版進關卡都另提交 11 個既有 program；等待中位數約 0.455／0.414 s。關卡總載入略增約 0.22 s，不能宣稱這一段改善。

平均中位數下降約 8.3%／13.7%；P99 沒有實質改善。這同時包含道路 surface 合併與材質共用的效果，未做分離兩項因素的額外 A/B，不能把全部差異歸因於單一因素。

新第一波尖峰範圍 284.70–298.64 ms，舊版 291.64–416.56 ms，仍有重疊。六輪首波最大間隔內均包含相同 5 個非共用材質 program，逐 shader source SHA-256 相同；新版本 LINK_STATUS 等待約占該間隔 75%。此處仍有特殊效果／既有首用程式成本，並未因材質整合消失。

## 驗證與產物

原始資料、全部 rAF／原生樣本、WebGL 呼叫與 source、實際畫面及功能 log：`.godot/test-results/rendering/shared_material/`。正式量測只使用 `before-final1..3.json` 與 `after-final1..3.json`；早期探針因漏算 viewport 縮放或使用未完成排版的按鈕座標而未走完流程，校正資料不混入正式統計。

通過：共用材質身分／表面參數／烘焙冪等性、14 個地塊與兩個塔的畫面、GPU 頂點及多姿勢畫面、混兵 slot／回收、原 Soldier 步態、外部匯入 fallback、啟動預熱、關卡準備、完整選單九次轉場、道路外觀與浮起／柱生長動畫。

載入回歸的測試點擊補上轉場後的排版等待；道路回歸把舊的「24 格應有一座木橋」改成獨立固定資料，不再要求可編輯正式地圖必須為 24 格。失敗／取消載入案例仍會輸出預期錯誤並驗證恢復。GPU 烘焙中途發現重複打包法線的量化累積，已改成一次寫入完整屬性；正式保留的是實際量測版本的網格資料，重新比對 arrays／AABB／format 一致。

一次性負載配方、量測程式與測試 Web 匯出於完成後清除，正式 Web 不包含探針；保留功能回歸、離線素材工具及這份摘要。

正式 `build/web` 已重新匯出，`web_loading_shell --live` 10／10，live=true、browser errors=0；本機 8765 服務保留，可直接試玩更新版本。
