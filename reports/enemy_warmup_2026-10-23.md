# 2026-10-23 敵人首次顯示預熱

## 結論與實作

將兵種代表模型、動畫與頭頂狀態的首次實際繪製移至等待介面後，32×32／256 混兵 Web 的首次出發最大 rAF 間隔由 6.68–6.88 秒降至 0.50–0.55 秒，兩輪最大值中位數降低約 92.3%。這是將首次初始化／繪製成本提前，不是讓載入成本消失，也不是證明所有停頓都來自 shader 編譯。256 人同刻生成仍有約半秒尖峰，尚未完全消除。

獨立預熱模組使用現有 renderer，在相機前逐一顯示各兵種代表，推進動畫並等待實際 draw；等待介面遮住代表、攔截輸入，完成後以實際 0.25 秒淡出。正式關卡涵蓋所有 ACT 的自訂兵種。代表不加入正式敵群、不建立路線、不消耗遊戲 RNG，清理後不增加移動迴圈的工作。Headless 跳過 GPU 預熱。

目前分支直接進入 level，沒有地圖選擇場景。等待介面為可共用、可編輯場景，日後可由地圖選擇到遊戲的轉場沿用；本次沒有宣稱已接上不存在的選單。單個材質的同步編譯仍可能讓等待畫面暫停，進度是完成兵種數，並非時間估算。新特效／執行期材質不保證已預熱。

## 方法

- 沿用 `tests/enemies/mixed_256.tscn`：801 道路格、16 塔、Soldier 86／Quickfeet 85／Heavy 85，生命 1,000,000、速度倍率 0.45；不改正式數值。每次按鈕同刻生成 256 人，再清場第二次出發。
- Godot 4.7.2 release，Compatibility，單執行緒 Web，GDExtension；可見 Edge 視窗 1280×800，DPR 1，WebGL 實際裝置為 AMD Radeon Graphics／ANGLE D3D11。未強制獨顯，未調整系統設定。
- 對照包與預熱包使用同一份當次遊戲程式及資源；對照包只在匯出時暫時跳過預熱，隨後立即還原來源。正式量測使用 `control-1/2` 與 `final-1/2`，順序 C1、F1、C2、F2，每輪獨立瀏覽器 context／程序；不聲稱清除了驅動快取。
- 網頁載入到 `MIXED_256_READY` 記錄為可操作時間，含本機下載、Wasm 啟動、地圖建立與預熱，並非純預熱時間。頁面可見、帶入前景並啟用 focus emulation。未固定模擬 delta，未進行 GPU 計時。
- 從按鈕操作前開始保存原始 rAF 時戳。首次／再次出發以操作後前 120 個間隔取最大值；每次生成後等待 12.5 秒，取最後 200 個間隔計算平均／P95／P99。這是瀏覽器畫面節奏，包含同步與排程，不能視為純 CPU 或 GPU 工時。本輪常見間隔約 16.7／33.3 ms，不與前一天不同環境的 FPS 直接比較。
- 四個正式程序均無 pageerror，遊戲 log 均確認兩次 256 人生成。探索性的 `before-*` 使用先前匯出包、`after-1` 使用初版預熱，不納入下表。

## 結果

| 測項 | 無預熱 C1／C2 | 預熱 F1／F2 |
| --- | --- | --- |
| 網頁載入至可操作 | 30.285／27.344 s | 34.932／34.657 s |
| 第一次出發最大間隔 | 6683.08／6883.13 ms | 550.02／499.91 ms |
| 再次出發最大間隔 | 83.19／83.14 ms | 83.33／83.33 ms |
| 首次出發後穩態平均 | 20.17／19.50 ms | 19.17／20.17 ms |
| 首次出發後穩態 P95 | 33.37／33.36 ms | 33.31／33.39 ms |

| 再次出發後穩態平均 | 19.58／21.00 ms | 19.83／18.92 ms |

載入可操作時間的兩輪中位數增加約 5.98 秒；首次出發最大間隔中位數減少約 6.26 秒。暖機後 P99 幾乎相同，沒有據此宣稱穩態 FPS 改善。樣本少且硬體速度可能波動，結論限於本次裝置與負載。剩餘半秒尖峰包含批次建立、首次執行及繪製等工作，本次沒有進一步分離歸因。

## 驗證及產物

- 新增 `tests/enemies/render_warmup.tscn` 功能回歸，實際 Windows／RTX 3050 Compatibility 繪製，確認 processing 鎖定、代表模型、RNG／波次隔離、可見 slot 清空、恢復出發，以及正式關卡入口與預熱中離場。
- `wave_spawn_groups`、`level_flow`、`level_teardown` headless 通過；後者覆蓋 48 種清理情境。沒有用 headless 幀率推估畫面效能，未跑全專案所有測試。
- 原始 JSON／畫面／log 位於 `.godot/test-results/enemies/warmup/`；功能截圖位於 `.godot/test-results/enemies/render_warmup*.png`。效能版本完成後僅追加等待文字中英文翻譯與正式關卡自訂兵種收集；手動負載的預熱與生成路徑不變，最終功能回歸另驗證這些收尾。
- 一次性瀏覽器計時程式與對照匯出用完清除，只保留原始結果、摘要、功能測試，以及使用者要求的手動 256 場景及其 Web 匯出。

Compatibility 需要實際顯示才能觸發首次準備，方法依 [Godot 官方 shader 編譯文件](https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html)；本次沒有使用不適用於 Compatibility／Web 的 Shader Baker。
