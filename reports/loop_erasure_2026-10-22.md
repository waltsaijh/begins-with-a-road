# 候選路線去環與 256 混兵量測（2026-10-22）

本次實際執行的結果。正式地圖、兵種與塔 Resource 未為測試改值；負載使用獨立合成地形及複製的兵種設定。基準為本次修改前的 candidate_routes（main HEAD `2d433de`），其餘場景、模型、戰鬥與渲染設定相同。

## 行為與測試

正式候選在建池時對完整逐格路線做 O(L) 去環，重建路長、實際經過的 vertex、格子索引及連續分段，再去重、以原始 evaluation 評分、套用門檻及建立 Uniform／Softmax 配額。分段 ID 識別保留的實體走法，不沿用已被剪接的 native edge ID。幾何分段登錄表不受兵種計畫修改；兵種新增的分段不常駐累積到共用表。

去環沒有加入出生、敵人移動或每幀更新。原生探索次數與 C++ 不變。已固定的當波路線不會因後續建池而改寫。

已通過 loop_erasure、route_planner、tile_costs、route_distribution、troop_profiles、multiple_starts，以及實際渲染的 debug_overlay。涵蓋跨分段去環、移除 vertex、被移除格子的再次進入、路線連通、分段重建、正負評分、嚴格門檻、去重後配額、多入口、固定波次快照與 F1 顯示。

## 負載與方法

- 32×32 範圍、801 格道路、16 個房間、窄接道及房間內障礙；放置 16 座 Sentry 後，入口圖為 91 個 vertex、19 個 region。合成格子入口為 `tests/fixtures/route_loop_fixture.gd`。
- Soldier 86、Quickfeet 85、Heavy 85，共 256 名，於同一刻出生。複製的兵種生命設為 1,000,000、速度倍率設為 0.45，波次基準速度 2.5，避免取樣期間死亡或抵達；不代表正式平衡數值。其餘採當前模型、動畫、血條、視覺避讓與塔攻擊。
- Windows，Ryzen 5 4600H、7.42 GiB RAM，Godot 4.7.2 stable editor runtime／template_debug GDExtension，Compatibility，RTX 3050 Laptop GPU（驅動 591.86），1280×800，VSync 關閉、FPS 不設上限，F1/F2 關閉。相機完整取景，near=0.1、far=150，已檢查實際地形與模型截圖。
- 渲染量測：修改前／後各三次，每次 3 秒暖機、12 秒取樣，記錄實際 wall 幀間隔。每次開始／結束均為 256 名存活。表格採三次結果的中位數，同時列出範圍；不是 headless FPS。
- 冷建池量測：headless 僅量 CPU 建池，交錯前後順序，一對暖機後各 12 次。每次使用全新 native planner，包含 prepare 與三兵種計畫，共用幾何池照正式流程重用；不是快取命中耗時，不包含模型生成。

## 結果

| 指標 | 修改前 | 去環後 |
| --- | ---: | ---: |
| 各計畫候選條目中有重複格子的路線 | 537 / 1,332 | 0 / 1,451 |
| 平均幀時間中位數 | 10.85 ms | 10.94 ms |
| 各次平均幀時間範圍 | 10.77–11.45 ms | 10.90–10.97 ms |
| P95 幀時間中位數 | 13.85 ms | 14.17 ms |
| P99 幀時間中位數 | 15.77 ms | 15.68 ms |
| 各次最大幀時間範圍 | 18.21–24.80 ms | 20.45–23.78 ms |
| 平均幀時間換算 FPS | 92.2 | 91.4 |
| 256 名行程快照／配額排程中位數 | 16.09 ms | 16.27 ms |
| 排程至 256 名全部生成，含首幀等待，中位數 | 64.61 ms | 71.43 ms |
| 三兵種完整冷建池平均 | 114.15 ms | 126.16 ms |
| 三兵種完整冷建池中位數 | 112.89 ms | 126.83 ms |
| 冷建池 P95／P99（12 次，兩者皆為當次最大值） | 127.33 ms | 128.24 ms |

候選條目總數包含共用幾何在不同兵種計畫中的使用，不是全圖不同路線總數。去環後條目增加，是因原始評分與門檻重算後，部分路線重新被保留；不是增加原生搜尋預算。三兵種的最佳原始分數由 55／7／−48 變為 55／7／−45，Heavy 不再透過重踩威脅格累積負分。

本次觀察到的穩態幀時間差異約 0.09 ms，落在短測波動內，沒有足夠證據認定穩態效能退化或改善。確定增加的是冷建池的一次性 CPU 工作：中位數約 +13.94 ms（+12.4%）。256 名一次生成仍有約 65–72 ms 停頓，這項工作沒有因去環而消失；不能宣稱完全無成本或普遍敵人上限。
