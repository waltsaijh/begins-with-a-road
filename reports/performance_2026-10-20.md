# 效能歷史摘要（2026-10-20）

這是清理前已完成量測的摘要，不是清理後重新執行的結果。一次性壓測場景、收集工具、逐幀 JSON 與截圖已移除，因此不能再用原入口重現或重新分析原始樣本。

環境：Ryzen 5 4600H、約 7.4 GiB RAM、RTX 3050 Laptop GPU，Godot 4.7.2 Compatibility。Windows 使用 editor runtime／debug GDExtension；Web 使用 Edge 155、headless、單執行緒 release 匯出與 release GDExtension。以下兩平台均使用 RTX，1280×800；建置不同，不能當成純平台速度比較。早期另測的 Edge 預設 GPU 是 AMD 內顯。

## 狀態顯示合批前後

固定合成負載每隻顯示血量、護盾、技能條及一個圖示；以實際渲染的 wall 幀間隔計時。30 幀暖機，60–180 幀取樣，至少 60 幀且超過 6 秒停止；同平台依序比較舊版繪製與 MultiMeshInstance2D。

| 2,048 隻完整狀態 | Windows 原 → 新 | Web 原 → 新 |
| --- | ---: | ---: |
| 平均幀時間 ms | 236.5 → 57.2 | 541.4 → 78.1 |
| P95 ms | 314.5 → 107.1 | 675.8 → 138.3 |
| P99 ms | 425.0 → 112.5 | 796.4 → 187.3 |
| 平均 FPS | 4.2 → 17.5 | 1.8 → 12.8 |
| 場景總 draw calls | 12,503 → 216 | 12,503 → 216 |

合批降低繪製成本，但投影、buffer 填寫、模型更新與移動仍有 CPU 成本。功能與像素比較保留於 `tests/enemies/enemy_status.tscn`；其中的舊版繪製 fixture 僅供外觀回歸。

## 複雜路網的 256 隻混兵

81×81 合成窄路環與五個 9×9 寬路區域，5,041 道路格、1,840 個獨立環、8 個入口。固定 seed 20261020 隨機生成 Soldier 68、Quickfeet 93、Heavy 95，共 256 隻；使用正式行程快照、配額與移動。測試副本搜尋預算為 256，沒有改正式 Resource；無塔攻擊、技能條及效果圖示負載。

相機全圖取景、far=1000，確認地形與模型實際可見。固定 1/60 秒步進，60 幀暖機、480 幀取樣；開始與結束均存活 256 隻。

| 平均幀時間 ms | 13.30 | 25.25 |
| P95 ms | 15.88 | 32.91 |

兩平台地圖、兵種／入口人數、候選數及完整行程指紋一致，當時 failures=0、Web errors=0。穩態幀率不能反映開波時數秒的同步規劃停頓。

## 後續量測約定

新量測同時記錄平均、P95／P99、初始化／生成尖峰及原始樣本；headless Windows 不用來推估渲染幀率。明列實際 GPU、建置模式、瀏覽器 rAF 限制與相機裁切範圍。原始產物留在 `.godot/`，需要保存時另外整理結論。

以上短測沒有涵蓋 standalone Windows release、手機、完整正式關卡密集戰鬥或長時間記憶體穩定性，不能推論通用敵人數量上限或無記憶體洩漏。
