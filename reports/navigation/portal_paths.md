# 區塊內全部等長最短路（2026-10-15）

本檔記錄局部最短路基礎版本。後續新增共用入口圖上的兵種 A*，最新全域選路與兩個實際場景效能見 `route_planner.md`；局部等長走法仍保留。

已在現有入口圖加入每個區塊內所有已標記節點的無向配對。每對以入口代表地塊為兩端，僅按移動步數求最短距離，完整保留所有等長走法。沒有新增中央岔點、全域選路、ZDD、flow field 或敵人。

## 資料與演算法

- C++ 核心 `native/src/portal_routes_core.hpp`：每區只使用該區 filled faces 的實際邊，避免把區塊外的細路誤當捷徑。
- 每入口一次 BFS。各配對共用來源／終點距離表；若 `dA[u]+1+dB[v]==dA[B]`，u→v 就屬於該配對的最短路 DAG。
- 每步來源距離嚴格增加，不會重複格子。沒有 DFS 路線列舉、走法數量上限或隨機刪路。
- 每個來源從全部其他入口反向傳播一次，建立所有配對 DAG 的顯示聯集，不逐配對掃過整區。選取單一配對時才掃描該區邊以還原方向。
- 路線數以 BFS 動態規劃計數。超過 INT64_MAX 時顯示 ≥9223372036854775807；只有計數飽和，距離與 DAG 不截斷。未實作依此計數均勻抽樣。
- 每區額外時間 O(E log E + P*(N+E) + P²)，資料空間 O(E+P*N+P²)。P 為該區入口節點數；不按完整最短路線數成長。

這裡的「任兩點」是指現有入口圖上屬於同區塊的已標記節點，包含位於區內的起終點；不為所有實體格子建立兩兩配對。沒有禁止重訪區塊。局部走法可能經過其他入口，日後接全域節點不重複的限制時須將實際途經入口納入，不能只檢查配對兩端。完整 window 仍保留，但本版沒有優化窗口任意銜接位置。

## 地圖顯示

- 總覽青線：全部入口配對最短走法的實體連線聯集，以及原有外部走廊；相同區塊內連線與共享區界連線去重。
- P／Shift+P：循環選配對；黃箭頭顯示該對的全部最短路 DAG，其他局部路線變淡。面板列出兩端、步數與路線數。
- Tab／Shift+Tab：循環選區塊、配對及外部道路。Esc 回總覽。G／L 維持顯示圖與節點編號切換。
- 仍為兩個 MeshInstance3D，沒有依完整路線建立繪圖物件。兩份原有場景與地圖資料未改動。

三入口範例：P1↔P2 是 4 步／1 條，P1↔P5 是 3 步／3 條，P2↔P5 是 5 步／10 條。

## 驗證

Windows 原生核心與 Godot 整合測試通過：

- 2×2、3×2、3×3 逐條窮舉所有 simple paths，獨立核對最短距離、全部最短路線數與 DAG 邊集合。
- 三入口所有配對；正反向 DAG；2×2 對角兩條等長路線；入口位置與更新後重新繪圖。
- 11×11 全滿對角：20 步、184756 條等長最短路，無刪減。
- 50×50 全滿對角：98 步，計數飽和後仍保留完整距離表與 4900 條 DAG 連線。
- 50×50、50 個入口：1225 個配對，共用 125000 個距離整數，不列舉完整走法。
- 內部障礙維持區塊邊界限制，9×9 交會點細迷宮沒有額外局部寬區路線。
- 原有 3000 張隨機拓撲測試與 16 種地塊接口／放置／鏡頭測試通過。

Windows／Web debug、release 擴充均已建置，Web 保持 Compatibility、WebGL 2.0、threads=false。瀏覽器測試核對三入口與內部障礙案例的配對、計數、完整距離表、顯示聯集與拓撲資料，和 Windows 完全一致；配對控制及正式主場景啟動通過，沒有瀏覽器錯誤。記錄於 `portal_paths_web.json`。
