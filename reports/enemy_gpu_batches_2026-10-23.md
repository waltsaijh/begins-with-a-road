# 三種兵 GPU 動畫與 Web 對照（2026-10-23）

Quickfeet、Heavy 已各自改用單一 surface 的 MultiMesh，與 Soldier 共用同一份 `enemy_walk.gdshader`。256 混兵的穩態平均幀時間在多數樣本下降；整體啟動／載入沒有縮短，首次非敵人 shader 尖峰也仍存在。以下均為本次實測，不沿用舊報告的數字。

## 實作與外觀

- 直接從專案目前保存的 runner／brute 場景烘焙網格、法線、色彩及支點，沒有重新生成原型模型。來源 `.tscn` 與 Walk 動畫仍保留作為編輯／回歸參考。
- 每個 GPU Model Resource 有獨立 MultiMesh、緊密 slot、預留容量與尾端搬移；頭頂狀態維持全敵群的獨立順序。開波先依模型合計人口預留，出生不建立逐隻模型或 AnimationPlayer。
- shader 以 uniform 接收步態參數，保留 Quickfeet／Heavy 原本 17 個關鍵影格的線性插值、各自週期、Quickfeet 的 3 倍播放，以及停止時凍結姿勢。Soldier 保留原本依距離推進、錯開相位及停止回中立的行為。路線、邏輯速度、傷害及正式兵種數值未改動。
- 未提供相符 GPU Model 的匯入模型，仍使用自己的材質、骨架與 AnimationPlayer。
- 啟動只繪製一個兵種 shader 代表。另外明確繪製並保留塔底座的純顯示網格，涵蓋世界共用色盤材質，不初始化塔或戰鬥。這項補充避免移除舊 CPU 模型後，把其原本附帶預熱的世界材質延後到進關卡。

逐頂點回歸涵蓋兩模型的全部頂點及七個動畫時間點：最大位置誤差 `1.20e-7` 世界單位，最大法線向量誤差 `1.07e-4`（網格法線儲存量化）。實際 Windows Compatibility renderer（RTX 3050）對照原場景與 GPU 的六張姿勢，前景平均 RGB 誤差最高 `0.000634`（0–1 範圍，約 0.16／255）；配色與姿勢一致。

## 本次量測條件

- `feat/outer_game_ui`、Godot 4.7.2 Compatibility、單執行緒 GDExtension Web release；未合併 reduced_graph 分支候選優化。
- Edge 155.0.4283.62 有視窗新瀏覽器 context，1280×800；實際 WebGL 裝置 `ANGLE (AMD, AMD Radeon(TM) Graphics (0x00001636) Direct3D11 vs_5_0 ps_5_0, D3D11)`。螢幕 rAF 基準間隔約 6.94 ms（144 Hz），不是 headless 或 Windows 原生 FPS。
- 從正式啟動 → 主選單 → 選圖 → 本局設定 → 正式 level 進入。僅在該次匯出的記憶體內替換 Level 配方，不修改正式地形、關卡或兵種資源。
- 32×32 範圍：16 個 7×7 房間、水平／垂直連接與環，共 809 道路格；入口 `(0,3)`、終點 `(31,27)`；放置 16 座 Sentry。此為本次合成地形，並非舊報告的 801 格配方。
- 同刻出生 Soldier 86／Quickfeet 85／Heavy 85；測試副本血量 1,000,000、移速倍率 0.45、波次速度 2.5，Quickfeet 的測試路線 base cost 為 0.25。正式雲、HUD、卡牌、狀態、塔與戰鬥均啟用。相機 size 42、near 0.1／far 150，完整地形與實際模型均在畫面內。
- 各版本三次新瀏覽器 session；每次透過真實「開始下一波」按鈕及原本 1.5 秒開場等待，連續量兩波。第一波觀察後只清空測試敵群，保留場景、路線池及 renderer，再手動開第二波。每波全部出兵後觀察 14 秒，穩態取最後 500 個 rAF 間隔；尖峰取該波整段觀察窗口。截圖在量測窗口結束後擷取。
- 攔截引擎原有的 WebGL 呼叫，沒有增加額外同步查詢。`LINK_STATUS` 耗時包含等待編譯／連結完成，無法細分 ANGLE 與驅動成本。

## 載入及編譯

下表為三次 session 各自數值的中位數；啟動時間包括該次本機資源下載、WASM／Godot 初始化、預熱與主選單首次繪製。關卡載入採原生轉場開始至結束，不把瀏覽器送出點擊的延遲算入。

| 項目 | 修改前 | 修改後 |
| --- | ---: | ---: |
| 導航至主選單可操作 | 30.86 s | 32.74 s |
| 選圖確認至關卡轉場完成 | 2.25 s | 2.26 s |
| 啟動期間全部 LINK_STATUS 等待加總 | 26.39 s | 28.03 s |
| 啟動 linkProgram 提交次數 | 66 | 66 |
| 啟動 compileShader 提交次數 | 132 | 132 |

三種兵的自訂 GPU 步態均使用同一份 shader；本次產生 6 個引擎 program 版本、12 個 shader stage 編譯，全部在啟動階段完成。最終三輪的這組 LINK_STATUS 等待為 3.99–4.63 秒，進關卡與兩波出兵皆沒有新增敵人步態 program。

整體編譯數量沒有下降：世界幾何仍需要原本的 StandardMaterial3D 程式，現在由明確的世界材質代表涵蓋。主選單、雲、UI、地形與特效也各有其他程式。不能把「三種敵人共用 shader」解讀為「整個遊戲只編譯一個 program」，本次亦沒有載入加速的證據。

## 驗證與產物

原始 JSON（含全部 rAF／原生幀樣本、事件及 WebGL 原始呼叫／source）、摘要與實際 Web 畫面：`.godot/test-results/enemies/gpu_batches/`。功能資料：`enemies/gpu_models.json`、`enemies/gpu_render.json` 及對照圖。六次正式 session 的 browser console error／page error 均為零。

本次通過：GPU 頂點／動畫／混兵回收與實際畫面對照、原 Soldier MultiMesh／walk render、外部模型材質與動畫 fallback、避讓、頭頂狀態、啟動／選圖載入、完整選單（九次轉場）、兵種與關卡流程回歸。Scene loading 的故意失敗／取消案例仍會輸出預期錯誤，最終 failures 為零。

兵種回歸初跑發現既有測試把 Quickfeet 倍率硬寫為 1.5，而目前正式資源已為 1.3；已比照原有 Heavy 的方式，只設定測試副本的凍結數值，不回改正式平衡，重跑 failures 為零。正式 Web 匯出已更新 `build/web`，不含探針；載入交接檢查最終 10／10、live=true、browser errors=0。首次收尾瀏覽器提前關閉的嘗試未計為通過，重開瀏覽器後完成上述檢查。

本次一次性合成配方、探針與量測匯出清除，不加入正式遊戲，也不保留新的 benchmark 入口。這是短時間、特定 AMD／Edge 的觀測，不代表通用敵人上限、跨 GPU 結論或長時間記憶體保證。
