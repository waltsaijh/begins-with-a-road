# 2026-10-23 從主選單進入的 32×32／256 混兵 Web 量測

## 結果

`feat/outer_game_ui`（`1ca92fe`）從真正主選單進入正式關卡後，第一次開波仍出現 5.30–6.53 秒的畫面停頓；同一局清場後第二波為 116.6–133.3 ms。256 人穩態約 45–46 FPS，P99 約 33.5–33.7 ms。選單流程沒有消除這個分支的敵人首次顯示停頓。

此分支尚未包含 `experiment/reduced_graph` 的候選池／批次分配優化與敵人顯示預熱。本次只測當前分支，沒有合併這些功能；不能把與先前報告的差異直接歸因於 menu 或視為預熱功能退步。

## 真實進入路徑與負載

- 以正式 `scenes/menus/main_menu.tscn` 為入口，使用瀏覽器滑鼠實際點擊「開始遊戲 → 下一步 → 開始作戰」，沿用 ScreenTransition 及正式 `scenes/level.tscn`。沒有直接啟動獨立負載場景，也沒有直接呼叫關卡的開波函式代替按鈕。
- 選圖預覽保留正式邊境前哨。只在確認開始作戰、畫面完整變白時，臨時工具以記憶體內容替換該次 Level Resource 的地形與波次配方；所有正式 `.tres`、場景及選單程式均保留原檔。
- 沿用先前的 32×32 合成布局：801 道路格、16 個房間、91 個入口圖節點、19 個寬區；起點 `(0,3)`、終點 `(31,27)`；16 座 Sentry 位於 `(x*8+1,y*8+1)`，x／y 為 0–3。
- Soldier 86、Quickfeet 85、Heavy 85，同刻生成。測試副本生命 1,000,000、速度倍率 0.45、波次速度 2.5；Quickfeet 的 path_base_cost 固定 0.25，對齊前次負載，其他設定沿用此分支。正式數值沒有改動。
- 正式 HUD、手牌、雲海、戰鬥、投射物及頭頂狀態均啟用，保留手動「開始下一波」與 1.5 秒開場；沒有用純場景或隱藏畫面代替遊戲。鏡頭 size 42、near 0.1、far 150，focus 為地圖中心，位置偏移 `(25,35,35)`；實際截圖確認地形、塔與敵人有繪製。
- 關卡配方為兩個相同波次。同局第二波只經由測試命令清除敵人與攻擊特效，保留地圖、候選、renderer 及已載入資源，再實際點擊正式開波按鈕。每波候選配額摘要 pool 為 1001；三輪兩波的生成數及觀察窗結尾存活數均為 256，兵種比例正確。

## 環境與方法

- Godot 4.7.2 release、Compatibility／WebGL 2、GDExtension、單執行緒；為當前分支重新建置 Web 原生擴充，避免沿用實驗分支的二進位。
- 可見 Edge 155.0.4283.62，1280×800、DPR 1；實際 renderer 為 `ANGLE (AMD, AMD Radeon(TM) Graphics (0x00001636) Direct3D11 vs_5_0 ps_5_0, D3D11)`。本次沒有切換 RTX 或更改系統設定；不宣稱這是 Windows 原生版的數字。
- 本機服務提供 COOP／COEP，三輪使用獨立瀏覽器工作階段，視窗置於前景並啟用 focus emulation；結果記錄 visible／focus 為 true。未清除 OS／GPU 驅動快取，沒有證明完全冷快取。
- 網頁側保存完整 requestAnimationFrame 時戳，從每次點擊前開始，到第 256 人生成後再觀察至少 16 秒。最大幀間隔從完整觀察窗取值；穩態取各波最後 300 個間隔，報告每輪平均、P95、P99。rAF 是畫面節奏，含瀏覽器排程及同步成本，不等於純 CPU 或 GPU 工時。未固定模擬 delta，本輪常見節奏約 16.7／33.3 ms。
- 前兩輪原始 JSON 的 `startup` 欄位最初只取前 120 幀，第二輪會漏掉延後發生的停頓，因此本報告與 `summary.json` 統一重讀完整 `frames` 計算觀察窗最大值。第三輪另保存生成後兩次 rAF 的確認點；舊原始紀錄保留未改寫。
- 負載就緒時間從確認開始作戰的 covered 訊號前開始，包含 28.0／30.3／28.0 ms 的合成地形配方建立、關卡建立、16 塔放置與相關重建、路線池準備及轉場；不是純場景讀檔時間，也沒有宣稱量到網頁冷啟動至主選單可操作的時間。
- 三輪有效執行均沒有 pageerror／Godot ERROR。工具調試期間曾有無效負載，已修正並排除，沒有納入結果。CPU 時脈、功耗與 GPU 分段未量測；沒有跨分支控制 A/B、長時間記憶體測試或敵人上限結論。
